## 0. 怎么用这份清单

**编号规则**：`M{里程碑}-{两位序号}`，例：`M1-05`。任务卡里「关联」列指向 PRD 章节，回溯需求时不用翻。

**状态标记**：`☐` 未开始 / `◐` 进行中 / `☑` 完成 / `⊘` 已裁剪

**三条使用规则**

1. **一次只开一个 ◐**：同时进行中的任务不超过 2 个（一个后端 + 一个前端可并行）。
2. **完成标准不过不改 ☑**：每条标准都写成可执行/可观察的形式；写不出标准说明任务还没拆到位。
3. **每周更新一次进度看板**（§1 底部），偏差超过 20% 就动裁剪池（§8），不要默默延期。

**任务卡模板**（以后加任务照这个写）：

```
| ID | 状态 | 任务（做什么） | 产出 / 主要文件 | 完成标准（可验证） | 依赖 | h |
```

**进度记录**

> 2026-11-18 完成 M0-01 ~ M0-05（21h）。两处与预估不同的地方，后续绕开：
> 1. `backend/alembic.ini` **必须是纯 ASCII**——Alembic 用系统 locale（本机 GBK）读取 ini，中文注释会直接 `UnicodeDecodeError`。
> 2. 老库首次接入 Alembic 时不要直接 `upgrade`：`script/init_db.py` 会先检测「有 users 表但没有 alembic_version」并自动 `stamp head`，否则报「表已存在」。
> 3. 模型凭据改为「默认空 + 调用时报 503」，启动不再因缺 key 崩溃；`/health` 会返回 `observability / llm / embedding` 三项状态。
>
> 2026-11-18 完成 M0-06 ~ M0-08（15h），M0 收尾。新增的坑：
> 4. `script/*.py` 里 `Path(__file__).resolve().parents[1]` 指向**仓库根**而不是 `backend/`，必须再拼 `/ "backend"`，否则 `dev.ps1 init` 第一次就 `ModuleNotFoundError`（已修 4 个脚本）。
> 5. `app/models/__init__.py` 的导入是**副作用注册**，被 lint 当未使用删掉后不会报错，只会让 Alembic 静默生成空迁移——已加 `__all__` 显式声明，并在文件头写明原因。
> 6. 可观测契约从 `start_trace/end_trace` 改为 `with trace(...)`：OTel 的 span 进出必须配对，成对 API 漏一次就悬挂。
> 7. 首次 `check_langfuse` 出现 TLS 握手超时，重试即通过（`us.cloud.langfuse.com` 从本机偶发慢）；`auth_check=True`、trace 已上报，说明是网络抖动而非代码问题。
>
> 2026-11-18 完成 M1-01 ~ M1-18（86h）。这一段踩到的坑，比 M0 密集得多：
> 8. **`script/init_db.py` 的 `stamp head` 会吞掉后续迁移**。老库迁移到 0001 时 stamp 的是当时的 head；等 0002（知识库）加进来后，`stamp head` 直接把库标成 0002，于是 0002 的建表语句一条都没执行，脚本却打印「数据库已就绪」。已改为**动态取迁移链起点 stamp baseline**，再 `upgrade head`。凡是「版本标记 + 增量迁移」的方案都有这个陷阱。
> 9. **`Base` 给所有模型加了 `created_at/updated_at`，手写迁移漏了一处就炸**：`kb_role_permissions` 没写时间列，插入授权时报 `column kb_role_permissions.created_at does not exist`。教训：手写迁移后要拿 `Base.metadata.tables` 对一遍列，而不是凭记忆。
> 10. **「重排不可用」其实是模型名写错了**：`gte-rerank`（老名字）在本账号返回 403 `AccessDenied`，看起来像「没开通额度」，实际可用模型是 `gte-rerank-v2`。教训：403 不一定是权限问题，先 `GET /compatible-mode/v1/models` 看清单，再怀疑账号。这个误判让系统白跑了几个小时的 dense 降级——**降级路径静默生效时，故障会被伪装成「效果不好」**。
> 11. **阈值必须跟着分数口径走，不能全系统一个数**。实测同一批问题：重排分把无关问题打到 0.006~0.14、相关问题 0.17~0.95；余弦相似度则把无关问题也能打到 0.69，反而把「介绍一下企业」这种泛问句打到 0.28。用 0.30 卡两种分数，结果就是**重排路径全拒、余弦路径全放**。现在：重排路径用 `RERANK_SCORE_THRESHOLD=0.15`（全局，10 正/10 负实测分界），余弦降级路径用库级 0.35/0.40。0.13~0.19 这段弱相关重叠区是已知局限，交给生成层兜底，M4 用评估集/LLM 判定再收。
> 12. **拒答时把分数清零，等于把排查线索一起删了**。原来 `top_score` 是「chunks[0].score 的属性」，拒答时 `chunks` 被清空 → 测试台显示 `top_score 0.0 / 命中 0 条`，看的人只能猜是「没权限」还是「没召回」。现在分数单独存字段、拒答时保留 `rejected_chunks`，测试台直接显示「top_score 0.2934 / 阈值 0.15（重排分）」。
> 13. **检索测试台的默认值本身就是一个坑**：默认选中列表第一个库（恭喜抽到 `kb_sop`）× 默认角色 `patient` = 必然 `no_permission`，一进页面就「一律拒答」。默认改成「全部库」；同时后端不再把「不传 kb_ids」偷偷兜底成「只看路径里那个库」——界面写着「全部库」却只搜一个库，是最费时间的错位。
> 14. **集合路由要用 `""` 而不是 `"/"`**：`POST /api/admin/kb` 会在 307 跳转后丢掉请求体（httpx 默认不跟随跳转），FastAPI 用空路径注册可以让无尾斜杠的地址直接命中。
> 15. **GBK 控制台打印 LLM 回复里的 emoji 会 `UnicodeEncodeError`**：只影响本地验证脚本，API 返回的是 JSON，不受影响。
> 16. 检索测试台的价值在真实数据上被验证了：同一句「七天无理由退货吗」，`patient` 命中 5 条（top 0.699），`visitor` 返回 `refused=true / low_score` 且 `filtered_out_kbs` 明确列出售后库——**权限是在向量检索层生效的**，不是接口层假装过滤。
> 17. 前端 4 个页面只验证到 `npm run build` 通过（4 个页面都产出了独立 chunk），**没有做浏览器点击联调**。Vant 弹窗层级、文件选择器、轮询在真实页面上的观感需要人工过一遍，这部分留给演示前自测。

> 2026-11-18 完成 M2-01 ~ M2-15（66h）。这一段踩到的坑，全都只在「真的两个 Agent 一起跑」之后才暴露：
> 16. **并行子 Agent 不能共用一个 `AsyncSession`**。第一版两个 `@` 一起跑时，`kb_search` 报 `IllegalStateChangeError: Method 'rollback' can't be called here`——检索服务在写 `hit_count` 时会 `commit/rollback`，两路并发就撞车。改成**每个子 Agent 一个独立会话**（`TurnContext.session_factory`）。这类 bug 单 Agent 演示永远看不到。
> 17. **子 Agent 会越界答题**。AI 药师去回答退货、订单售后去回答「哺乳期能不能吃药」，汇总后变成两份互相矛盾的答案。修法不是改 prompt 模板，而是由运行时统一追加「职责边界」（`SCOPE_RULES`）：只答自己那部分、不评价别人、300 字以内。
> 18. **「让模型做汇总」是把延迟和风险都翻倍**。第一版多 Agent 走 LLM 汇总，实测 9.4s（两路并行只要 3s），而且模型会把 A 的结论说成 B 的。改成**确定性合并**（来源由代码拼、引用按全局重编号），延迟降到 5.0s、归因零错误；`CHAT_LLM_SYNTHESIS=true` 仍可切回模型融合。
> 19. **venv 里的 `redis` 包是坏的**（`__init__.py` 是 2.0.0、`client.py` 是 Python2 语法），`import redis.asyncio` 直接 SyntaxError，而所有缓存/限流调用都 `except Exception: pass` → **ACL 缓存与对话限流静默失效**，M1 时误以为「缓存生效了」。`pip install --force-reinstall redis==8.1.0` 后：`from_cache=True` 真的出现、第 3 次对话正确返回 429。教训：降级路径必须留下可观测痕迹（哪怕日志，也要能在自检里看到）。
> 20. **`supervisor_enabled` 忘了接线**：`decide_route` 写好了、`TurnContext.route_llm` 也留了，但 `chat.py` 传的是 `None`，于是「没 @ 的提问永远直连主 Agent」。实测路由生效后：企业问题 → `company_intro`（0.98）、退货问题 → `order_after_sale`（0.95）、「嗯」→ `clarify`（0.05）。
> 21. **LangGraph 节点用 `lambda` 包协程会被当同步函数**：`add_node("route", lambda s: self._route_node(s, ctx))` 不会报错，但协程**永远不被 await**（表现为事件流里只有一句 `error`）。必须用 `async def` 包装。
> 22. **流式下引用序号不能重排**：`sanitize_citations` 会把 citation 重排成连续序号，但流式正文已经发出去了，重排后就对不上。现在保留原序号、前端必须按 `citation.index` 匹配（`done.citations` 可能是不连续的 `[1,4,6,7]`）。

> 2026-11-19 完成 M3-01 ~ M3-12（48h）。这一段的坑集中在「跨会话 / 跨进程 / 跨进程重启」——
> 单机单会话测试永远碰不到：
> 23. **Langfuse 的 `propagate_attributes` 是模块级函数，不是 client 方法**。M2 写成
>     `client.propagate_attributes(...)`，异常被 `except` 吞掉 → **所有 trace 静默降级成 no-op**，
>     面板上什么都看不到。M3 联调时从日志里发现。另外 M2 的 LLM 调用根本没传
>     `config={"callbacks": sink.callbacks()}`，所以就算 trace 建起来也没有 generation（token/成本）。
>     两处都修了；教训：**观测链路的降级必须在 `/health` 或日志里可见**。
> 24. **Windows 上 uvicorn 默认给的是 ProactorEventLoop**，psycopg 异步连接直接抛
>     `InterfaceError`。而且 uvicorn 0.36+ 的 `asyncio_loop_factory(use_subprocess=False)`
>     **无视**你先设的策略——`--reload` 才会给 Selector。最终加了 `backend/serve.py`：
>     自己建 `SelectorEventLoop` 跑 `Server.serve()`。`dev.ps1 backend` 已切过去。
> 25. **短期记忆的摘要不能每轮都重做**：用 `conversations.summary_upto` 记住「已浓缩到第几条」，
>     否则 20 轮之后每轮都要把全部历史再摘要一次（一次多 1~2s）。
> 26. **记忆向量不能排除敏感项**：第一版为了「安全」把 `risk` 类型排除在 Milvus 之外，
>     结果「我对青霉素过敏」这条永远检索不到，跨会话记忆直接失效。正确做法是照常检索、
>     在注入措辞与用户删除权上控制风险。
> 27. **记忆必须过相关性门槛**：不设门槛时，问「订单退款多久到账」也会把过敏史塞进 prompt。
>     实测余弦：相关用药问题 0.36~0.58、无关问题 0.17~0.25 → 门槛定 0.30。
> 28. **语料改写要用「重叠系数」而不是纯 Jaccard**：「我对青霉素过敏」vs「我青霉素过敏」
>     的 Jaccard 只有 0.57（被判成不同记忆），加权后的相似度 0.71 才过得了去重线。
> 29. **`--reload` 反复重启会留下多个监听 8013 的僵尸进程**，请求被分到旧进程上表现为
>     「所有接口都超时」。排查方法：`Get-NetTCPConnection -LocalPort 8013 -State Listen`
>     看是不是有多个 PID，按端口 owner 杀，而不是按进程名。
> 30. **发送方会收到自己发的 WS 消息**（一个会话一条广播频道）。前端用 `client_message_id`
>     认领本地乐观气泡（服务端原样回带），而不是「只按 `message.id` 去重」——
>     本地气泡一开始没有服务端 id，光去重会让自己的消息显示两遍。
> 31. **实时通道必须在排队阶段就连**。第一版只在 `human_active` 时才连 WS，于是形成死锁：
>     患者不知道「已被接管」→ 不连 → 永远收不到接管帧。改成 `handoff_pending` 即连，
>     无论翻不刷新都能在 1s 内看到「客服已接入」。
> 32. **会话状态不能只活在内存里**。刷新丢记录不是后端没存（`messages` 一直在落库），
>     而是前端没把 `conversation_id` 留在地址栏。`?c=<会话 id>` + `GET /api/conversations/{id}`
>     才是「刷新可恢复」的最小实现；坐席端同理用 `?ticket=`。
> 33. **空 assistant 行会变成坐席眼里的「AI 发了条空白消息」**：流式回答先落空行、正文流完才写回，
>     而敏感场景在生成**之前**就建单。两头一对，坐席点进工单正好看到空气泡。
>     列表接口过滤空 assistant 行 + 详情 3s 软刷新，才是完整修法。
> 34. **状态帧只发 `{ticket_id, status}` 不够**：患者端要把排队条切成「客服已接入」，
>     还得知道坐席名和剩余时限。统一改成发完整 `ticket_payload`，少一次往返、
>     也避免两个端各自拼一份不同形状的工单对象。
> 35. **`done` 之后前端会立刻断开，落库不能写在 `finally`**。FastAPI 的流式生成器在连接断开时被取消，
>     `finally` 里的 `await commit()` 大概率不会执行——表现就是「AI 明明回答了，刷新后那条回答不见了」。
>     正确顺序是：**先落库、再发 `done`**，`finally` 只做中断兜底。
> 36. **路由也要看上下文，但不能拿改写句去路由**。实测「这个药怎么购买」：
>     带历史用原句路由置信度 0.62，用消解后的「花红消肿止痛酊怎么购买」反而只有 0.55。
>     所以消解结果只用于检索与子 Agent 的当前问题，路由仍用原话 + 历史；
>     置信度门槛也从 0.6 调到 0.5（小模型对短句的自我评分普遍偏低）。
> 37. **「结束会话」应该是 AI 接管，而不是关掉会话**。第一版把会话置 `closed`，用户想再问就只能新开会话，
>     上下文和记忆都断了。改成 `resolved` + 会话回 `bot_active`：AI 接着答，再转人工建新工单。
> 38. **加角色时别忘了 `AnyUser`**。M1 引入 `support` 时只改了路由与 RBAC，没把 `SUPPORT` 加进
>     `app/api/deps.py` 的 `AnyUser`；结果客服登录后 `auth.login()` 里的购物车请求 403、
>     整个登录 Promise 被 reject，前端只看到一句「权限不足，仅限管理员和医生操作」。
>     两处都修了：`AnyUser` 加 `SUPPORT`，且登录时购物车拉取失败不再影响登录态。
> 39. **流式合规改写要「扣尾巴」，且必须处理否定句**。token 发出去就收不回，所以要先扣住可能是敏感词前缀的字；
>     但只做逐词替换会把「更不能说它能根治」改成「…能缓解」，意思正好反——正确做法是把「否定词 + 12 字内 + 违禁词」
>     整句改写成「不能给出绝对化的疗效承诺」。
> 40. **检索阈值判断不了「资料能回答这个问题」**。问「花红片能治糖尿病吗」，说明书因为都提到花红片而高分命中，
>     模型只能硬套。加一道范围守卫（问题里的疾病词在召回片段里完全没出现就拒答）后，拒答准确率 0.86 → 0.94。
> 41. **评估与落库不能分两次 `asyncio.run`**。asyncpg 的连接池绑定创建它的事件循环，第二次 run 会拿到已关闭循环上的连接
>     （报 `'NoneType' object has no attribute 'send'`），表现为「评估跑完了但没写进 eval_runs」。
> 42. **LLM judge 会吃掉评估时间**：6 条全链路 + judge 跑了 150s，其中 120s 是 judge 超时。给它单独的 45s 超时并放到
>     httpx 客户端关闭后执行；judge 只是「加分项」，不该拖死整轮评估。
> 43. **`messages` 加列要记得 `Base` 混入的 created_at/updated_at**：`eval_runs` 迁移漏了这两个字段，
>     查询直接 `column created_at does not exist`。迁移里手写表结构时，`Base` 的字段不会自动出现。
> 44. **压测数字要如实写**。5 并发 p95 10.6s（模型侧限流/吞吐），50 并发只会测出 429；README 的门槛写「目标」，
>     实测写实测，比把数字凑到 6s 以内更有说服力。
