# M2 接口契约（前端 ↔ 后端）

> 这份文档是 M2 前后端并行开发的**唯一契约**。改这里之前先改代码，改了两边都要重跑。
> 后端只认结构化 `mentions`，**绝不**从文本里正则抠 `@`（PRD FR4.2）。

## 1. `GET /api/agents?visible=1`

权限：公开（游客可）。按当前登录角色的 `allowed_roles` 过滤，`status=active` 才返回，按 `sort_order` 升序。

```json
{
  "code": 200, "message": "ok",
  "data": [
    {
      "code": "drug_consult",
      "name": "AI 药师",
      "avatar": null,
      "description": "基于药品说明书回答用法用量、禁忌、不良反应",
      "ui_mode": "chat",
      "entry": "/agents/drug_consult",
      "tools": ["kb_search", "product_lookup", "escalate_human"],
      "kb_codes": ["kb_drug_manual"],
      "capabilities": ["知识库：药品说明书", "工具：药品查询", "工具：转人工"]
    }
  ]
}
```

## 2. `POST /api/chat/stream`

权限：公开（游客可用；游客角色记为 `visitor`）。返回 `text/event-stream`。

### 请求体

```json
{
  "agent_code": "drug_consult",
  "conversation_id": null,
  "client_message_id": "0b1f…（uuid，前端生成，必填）",
  "message": "@订单售后 我刚买的这单能退吗？",
  "mentions": [{"agent_code": "order_after_sale", "name": "订单售后", "offset": 0}],
  "context": {"product_id": null, "order_id": null}
}
```

- `agent_code` 省略时用主 Agent `drug_consult`。
- `mentions` 里只放 `agent_code`；`name`/`offset` 仅用于展示与前端回填，后端以 `agent_code` 为准。
- `context.product_id` 传了就在检索 query 里带上药品名。

### 帧格式

```
event: delta
data: {"text":"根据说明书"}
<空行>
```

事件顺序（正常路径）：

| 顺序 | event | data |
| --- | --- | --- |
| 1 | `meta` | `{conversation_id, message_id, trace_id}` |
| 2 | `route` | `{mode, agents:[{code,name,role}], confidence, rationale}` |
| 3 | `agent` | `{code, name, phase:"start"}` — 每个子 Agent 一条，可能并行到达 |
| 4 | `retrieval` | `{agent_code, kb_ids, hits:[{doc_title,section,score}], top_score, refused}` |
| 5 | `tool` | `{agent_code, name, ok, summary}` — 只有调用工具时才有 |
| 6 | `agent` | `{code, name, phase:"done", ok, elapsed_ms}` |
| 7 | `citation` | `{index, doc_title, section, page, snippet, url, agent_code}` — 先于 `delta` |
| 8 | `delta` | `{text}` — 多次 |
| 9 | `handoff` | `{ticket_id, queue_position, reason}` — 仅建议转人工时 |
| 10 | `done` | 见下 |

`done.data`：

```json
{
  "message_id": "…",
  "latency_ms": 3240,
  "usage": {"input_tokens": 0, "output_tokens": 0, "cost": 0},
  "citations": [{"index": 1, "doc_title": "花红片说明书", "section": "禁忌", "page": 2, "snippet": "…", "url": "/kb/…", "agent_code": "drug_consult"}],
  "contributors": [{"code": "order_after_sale", "name": "订单售后", "summary": "该订单已签收，支持 7 天无理由退货"}],
  "guardrail": {"passed": true, "flags": []},
  "suggested_actions": [{"type": "handoff", "label": "转人工客服"}],
  "replayed": false
}
```

### 失败语义

- **开始流之前**的校验失败 → 普通 JSON + 对应 HTTP 状态码（`401` 未登录、`403` 无权用该 Agent、`400` 伪造 agent_code、`429` 限流）。
- **流开始之后**的失败 → `event: error`，`data: {code, message, retryable}`，随后连接关闭；不再发 `done`。
- 幂等：同一 `client_message_id` 在 5 分钟内重复提交，直接重放上次结果（`done.replayed=true`），不重复扣费。

## 4. 硬约束

1. **不新增 npm 依赖**：只用已有的 `vue`、`vant`、`lucide-vue-next`、`marked`、`pinia`、`axios`。
2. SSE 用 `fetch` + `ReadableStream`，不用 `EventSource`（它不支持 POST 与自定义 header）。
3. `@` 只在**非输入法组合态**触发（`compositionstart/end`），候选按 `fetchAgents()` 返回的列表过滤。
4. 停止生成 = `AbortController.abort()`，之后不得再向该消息追加 token。
5. 生产环境不显示调试面板（`import.meta.env.DEV` 才显示 `RetrievalPanel` / `TraceLink`）。
6. 药品详情页视觉不能回归：保留原 `.ai-assistant-card` 结构、配色与快捷问题。
