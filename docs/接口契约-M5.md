# 接口契约 · M5（角色工作台与导览）

> 本文只覆盖 M5 新增的 4 个聚合接口，以及工作台的信息架构约定。
> 已有接口（会话 / 记忆 / 工单 / KB / 观测）见 `接口契约-M2.md`、`接口契约-M3.md`。

## 0. 通用约定

- 全部返回 `{code, message, data}` 信封（`ResponseModel`），与既有接口一致。
- 时间一律 ISO8601 UTC，`...Z` 结尾（浏览器按本地时区渲染）。
- **百分比返回 0~1 小数**，货币单位元，耗时单位毫秒（`*_ms`）或秒（`*_seconds`）。
  格式化只在前端发生——不要在某个接口里返回 `"94%"`。
- 只读聚合，不写库、不调用 Langfuse / Milvus（工作台首屏不能被外部依赖拖慢）。

## 1. `GET /api/me/workbench`

**权限**：任意登录角色（patient / doctor / support / admin）。
**用途**：患者 / 医生 / 客服工作台首屏。

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "role": "patient",
    "role_label": "患者",
    "user": {"id": "uuid", "username": "patient", "role": "patient"},
    "stats": {
      "orders": 0,
      "orders_pending": 0,
      "orders_paid": 0,
      "cart_items": 0,
      "cart_amount": 0.0,
      "conversations": 42,
      "memories": 13,
      "open_tickets": 0
    },
    "recent_conversations": [
      {
        "id": "uuid",
        "title": "这药能根治咽炎吗",
        "agent_code": "drug_consult",
        "status": "bot_active",
        "message_count": 2,
        "updated_at": "2026-11-18T18:10:21.762084Z"
      }
    ],
    "recent_orders": [
      {
        "id": "uuid",
        "status": "shipped",
        "total_amount": 128.0,
        "created_at": "...Z",
        "item_names": ["花红片"],
        "item_count": 1
      }
    ],
    "ticket": {
      "id": "uuid",
      "status": "resolved",
      "reason": "用户点击转人工",
      "trigger": "explicit",
      "conversation_id": "uuid",
      "queue_position": 0,
      "created_at": "...Z",
      "accepted_at": "...Z",
      "closed_at": "...Z"
    },
    "memory": {"enabled": true, "items": 13, "summary": ""},
    "generated_at": "...Z"
  }
}
```

**按角色变化的 `stats`**：

| 角色 | 字段 |
| --- | --- |
| patient | `orders / orders_pending(已发货待收货) / orders_paid / cart_items / cart_amount` |
| doctor | `products / libraries / documents / chunks / consults_24h` |
| support | `queued / assigned / offline / resolved / resolved_today / mine` |
| 公共追加 | `conversations / memories / open_tickets` |

**约定**：

- `recent_orders` 只对 patient 有内容，其它角色返回 `[]`（不返回 `null`，前端少一个分支）。
- `ticket` 为 `null` 表示没有工单；有工单时给**最近一条**（含已结束），前端自己判断是否展示。
- `memory.summary` 截断到 200 字：工作台只显示摘要，完整内容去 `/api/me/memory`。
- 算不出来的指标**不返回字段**，前端显示「—」，不要返回 0 冒充。

## 2. `GET /api/public/stats`

**权限**：无（游客可用）。**只读、不含任何用户数据。**

```json
{
  "data": {
    "kb": {"libraries": 4, "documents": 13, "chunks": 86},
    "agents": 4,
    "eval": {
      "available": true,
      "cases": 4,
      "recall_at_5": 0.75,
      "mrr": 0.75,
      "refusal_accuracy": 1.0,
      "ran_at": "...Z"
    },
    "generated_at": "...Z"
  }

```

- `eval.available=false` 时只有这一个字段（没跑过评估不是错误）。
- 前端落地页在请求失败时显示「—」，不得白屏。

## 3. `GET /api/support/stats`

**权限**：support / admin（其它角色 403）。

```json
{
  "data": {
    "window_hours": 24,
    "accepted": 2,
    "resolved": 2,
    "queued": 0,
    "avg_wait_seconds": 20,
    "max_wait_seconds": 33,
    "generated_at": "...Z"
  }
}
```

- `avg_wait_seconds` = `accepted_at - created_at` 的均值，只统计 24h 内**已被接管**的工单。
- 前端在拿不到时**整条隐藏**，不影响队列本身。

## 5. 公开药品目录（商城链路）

`GET /api/products` 是后台接口（admin/doctor）。C 端要逛药，所以单独开只读目录，
**无需登录**，只返回展示字段：

```json
GET /api/catalog/products?keyword=花红&category=妇科用药
{
  "data": [
    {
      "id": "uuid",
      "name": "花红片",
      "generic_name": "一点红",
      "category": "妇科用药",
      "dosage_form": "片剂",
      "spec": "0.3g×24片",
      "price": 28.0,
      "original_price": 35.0,
      "stock": 120,
      "image_url": "https://...",
      "indications": "清热解毒，燥湿止带……",
      "on_sale": true
    }
  ]
}
```

- `GET /api/catalog/categories` → `["妇科用药", "骨骼肌肉系统用药", ...]`（去重排序）。
- `keyword` 同时匹配 `name / generic_name / indications`，大小写不敏感（`ilike`）。
- 上限 60 条：目录规模小，前端不做分页；真要上千条再引入游标。
- **加购不在这里**：仍走 `POST /api/cart`，需要登录——目录是只读的，购物车才有写权限。

## 6. `overview` 的增量字段

`GET /api/admin/observe/overview` 在 M4 基础上追加两个字段（旧字段不变）：

```json
{
  "trend": [
    {"date": "2026-11-18", "turns": 60, "refusals": 1, "conversations": 57, "tickets": 2}
  ],
  "todos": [
    {
      "key": "queued_tickets",
      "label": "排队待接管工单",
      "value": 0,
      "tone": "ok",
      "to": "/support",
      "note": "坐席接管后可继续对话"
    }
  ]
}
```

- `trend` 长度 = `days`，**没有数据的天也返回 0**（折线不能断）。
- `todos` 固定 5 项，`value=0` 时 `tone=ok`；前端只渲染 `value>0` 的项。
- `to` 是前端路由，后端不改前端路由时只影响跳转目标。

## 7. 前端信息架构约定

| 角色 | 路由 | `?tab=` 取值 |
| --- | --- | --- |
| 患者 | `/patient` | `overview` `chat` `orders` `cart` `mine`（会话 + 记忆） |
| 医生 | `/doctor` | `overview` `drugs` `consult` |
| 管理员 | `/admin` | `overview` `orders` `quality` `system` |
| 客服 | `/support` | 无 Tab（双栏 + 统计条） |

规则：

1. **Tab 用组件内 state，不拆嵌套路由**：换 Tab 是「同一屏换数据」，拆路由会让滚动位置和流式状态全丢。
2. **Tab 必须写进 URL**，用 `router.replace`（不污染历史），刷新/分享能回到同一屏。
3. **需要保活的 Tab（聊天）用 `v-show`**，其余用 `v-if`；Shell 不用 `<Transition :key>`，否则卸载即断流。
4. **按需加载**：首屏只拉「聚合接口 + 当前 Tab」，切到哪个 Tab 再拉哪个。
5. 旧路由（`/orders`、`/me/memory`、`/service`、`/admin/kb`）**保留**，工作台只是新入口，不做删除。
6. **底部 Tab ≤ 5**：患者原 6 个（会话、记忆分开），合并成「我的」；新增 Tab 前先想能不能并进已有面板。
7. **列表页进 KeepAlive 白名单**（`App.vue` 的 `CACHED`，按组件 `name` 匹配）：返回时保留筛选、已加载数据与滚动位置；带参数页（对话、详情）不进白名单，否则不同 id 会复用同一实例。
8. 长列表（>8 行）一律放进 `max-height + overflow-y` 的滚动区，不做整页拉长。
9. **返回统一走 `utils/nav.goBackOr(router, fallback)`**：优先 `history.back()`（Vue Router 写在 `history.state.back`，刷新后仍在），只有「直接打开链接 / 新标签页」才落到 `fallback`；禁止页面写死 `router.push('/agents')` 这类固定返回。
10. **同一业务对象只有一个展示组件**：药品卡 `ProductCard`（`variant=shop|manage`）、购物车行 `CartItem`、订单卡 `OrderCard`、订单明细行 `OrderItem`。新增页面只允许复用，不允许复制一份。

## 8. 图片上传与静态资源（修复）

### 8.1 `POST /api/upload/`

**权限**：登录即可（上传发生在后台录入弹窗，接口本身不校验角色）。
**请求**：`multipart/form-data`，字段名 `file`。

**为什么这条要单独写**：修复前它返回 500，而且文件其实已经写进 `static/uploads` —— 前端只看到「图片上传失败」，后台却多了一个没人引用的文件。原因是
`response_model=UploadResponse`（顶层 `url`）与实际的 `ResponseModel` 外壳不匹配，FastAPI 响应校验失败。

```json
{
  "code": 200,
  "message": "success",
  "data": {"url": "/static/uploads/71573d0080f74fadbfd7ad4e4587fce7.png"}
}
```

| 校验 | 规则 | 失败 |
| --- | --- | --- |
| 扩展名 | `jpg/jpeg/png/webp/gif` | 400 `只支持 gif/jpg/jpeg/png/webp 格式的图片` |
| 空文件 | `len(content) > 0` | 400 `文件内容为空，请重新选择图片` |
| 体积 | ≤ 5MB | 400 `图片不能超过 5MB` |

约定：

1. `data.url` **一定是正斜杠**的站内绝对路径，直接塞进 `<img src>`；
2. 目录按代码位置定位（`backend/static/uploads`），不依赖启动时的工作目录；
3. 文件名为 uuid，不使用用户上传的原始文件名（避免中文/路径穿越/重名覆盖）。

### 8.2 静态访问

`GET /static/**` 由 `StaticFiles` 直出（绝对路径挂载）；Vite dev 已代理 `/static` → `:8000`。
前端所有图片都过 `utils/image.js`：

- `normalizeImageUrl`：把历史数据里的 `\\` 纠正成 `/`；
- `imageUrl`：空值直接给内联 SVG 占位；
- `onImageError`：外链（hhyy.com）被防盗链/断网时换成占位图，打 `dataset.fallback` 防死循环。

> 已存在的历史脏数据（`/static/uploads\xxx.png` 且文件已丢失）**不回写数据库**：读取时纠正 + 裂图兜底即可，避免为了演示数据写迁移。

## 9. 管理员订单管理（新增）

之前后台没有任何「查看全部订单」的入口：管理员必须先知道订单号，再进详情页点「模拟发货」，等于没有订单管理。

### 9.1 `GET /api/orders/admin/all`

**权限**：`admin`（其它角色 403）
**Query**：`status`（`all` / `pending` / `paid` / `shipped` / `completed` / `cancelled`，空 = 全部）、`keyword`（用户名模糊）、`limit`（1~200，默认 50）

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [
      {
        "id": "uuid",
        "status": "paid",
        "total_amount": 81.46,
        "created_at": "2026-11-19T05:20:00Z",
        "user_id": "uuid",
        "username": "patient",
        "item_count": 2,
        "items": [
          {"product_id": "uuid", "name": "花红片", "quantity": 2, "unit_price": 25.0, "image_url": "/static/uploads/a.png"}
        ]
      }
    ],
    "counts": {"paid": 2, "shipped": 1, "completed": 1, "cancelled": 1},
    "total": 5,
    "pending_ship": 2,
    "filter": {"status": "paid", "keyword": "", "limit": 50}
  }
}
```

- **路由顺序**：必须声明在 `GET /api/orders/{order_id}` 之前，否则 `admin` 会被当成 UUID 解析 → 422。单测 `test_admin_order_routes_are_declared_before_dynamic_order_id` 钉住这一点。
- `counts` 统计的是**全部订单**（不受 `status` 筛选影响），前端 Tab 角标直接用。

### 9.2 `GET /api/orders/admin/summary`

工作台角标用的极简计数：`{counts, total, pending_ship, in_transit, revenue}`。
`revenue` 只累计 `paid + shipped + completed`，不含取消单。

### 9.3 `PUT /api/orders/{order_id}/ship`（行为变更）

- 仍然只允许 `admin`；
- **只有 `paid`（待发货）可以发货**，其它状态返回 400 并带上当前状态。
  修复前对任意状态都静默返回「发货成功」，管理员点一下以为发了，实际状态没变。

### 9.4 `GET /api/orders/{order_id}`（行为变更）

管理员可以看**任意**订单详情（订单管理页点「详情」）；其它角色仍只能看自己的。
详情页里「取消订单」按钮对管理员隐藏——取消是下单人的动作，后端也只认本人。
