# 8 分钟演示脚本

> 目标：让面试官在 8 分钟内看到「RAG 全链路 + 多 Agent + 记忆 + 人机协作 + 治理与评估」，
> 每一步都有**可验证的产物**（引用、事件、工单、指标数字），而不是「你看它能聊天」。

## 演示前 5 分钟（务必执行）

```powershell
# 1. 依赖在跑
.\script\dev.ps1 status          # pg / redis / milvus 都要 Up
# 2. 后端（Windows 必须用 serve.py，checkpointer 需要 SelectorEventLoop）
cd backend; $env:PYTHONPATH="$PWD"; $env:PORT="8000"; ..\.venv\Scripts\python.exe serve.py
# 3. 前端
cd frontend; npm run dev         # http://localhost:5173
# 4. 重置演示数据（不动知识库 / 账号 / Agent）
$env:PYTHONPATH="backend"; .venv/Scripts/python -X utf8 script/reset_demo.py
# 5. 自检
curl http://127.0.0.1:8000/health   # redis / checkpointer 都要 ok
```

浏览器准备**两个标签页**（同一浏览器即可，登录态按标签页隔离）：

- 标签页 A：`localhost:5173` → 登录 `patient/123456`
- 标签页 B：`localhost:5173/support` → 登录 `support/123456`

> 兜底：先录一段 8 分钟屏，Milvus 冷启动 90s / 模型偶发超时的时候直接放录屏。

---

## 0:00–0:40 开场（40s）

一句话定位：「一个医药场景的 Agent 系统，重点不是能聊，而是**答得有依据、管得住、可度量**。」

打开 README 的架构图，指三处：**RAG 全链路**（检索→重排→引用）、**Agent 配置化**（加 Agent 不改代码）、
**三层防越权**（接口 RBAC / 数据 ACL / 工具归属）。

## 0:40–2:00 知识库问答（80s）

标签页 A → `/agents/drug_consult` → 点右上角 **✨ 演示提问** → 「跌打扭伤怎么办」：

1. 回答里出现 `[1]` 角标 → 点开看到《花红消肿止痛酊说明书》原文片段（**引用可溯源**）；
2. 回答末尾有免责声明（**合规**）；
3. 展开 DEV 面板 → `retrieval` 里有 top-k 分数与阈值（**打分口径**）。

再点一条库外问题：「花红片能根治糖尿病吗」→ 走**拒答**（范围守卫），不是硬编。
口播：「主题相关 ≠ 资料能回答，这一条是拒答准确率里最难的部分。」

## 2:00–3:00 多 Agent 协作（60s）

面板里点「@AI药师 @订单售后 哺乳期能吃花红片吗？我这单能退吗？」：

- 两段结论分别标注来源，**并行生成**（总耗时 ≈ 慢的那一路）；
- 口播取舍：「默认不做模型融合——确定性合并不会把 A 的结论说成 B 的，而且省一次完整生成。」

## 3:00–4:00 上下文与记忆（60s）

1. 同一会话追问「它有什么禁忌」→ 回答针对**上一个药**（`route.rewritten` 里能看到指代被补全）；
2. 说「我对青霉素过敏」→ 右上角出现「记忆」徽标；
3. 点右上角 **新会话** → 问「这个药我能吃吗」→ 回答含「您上次提到…」，`memory_used=1`。

口播：「短期靠 checkpointer + 10 轮窗口 + 滚动摘要，长期靠 `user_memories` + Milvus，
注入前过 0.30 的相关度门槛——不然问退款也会塞过敏史。」

## 4:00–5:20 转人工 + 坐席（80s）

1. 标签页 A 说「我吃了不舒服，我要投诉」→ **立刻**弹出排队条（敏感词在生成前就建单）；
2. 标签页 B 的 `/support` 队列里 1 秒内出现这条工单，卡片上有**交接摘要**（诉求 / 已尝试 / 风险 / 建议话术）；
3. 点「接管」→ 标签页 A 立刻变「客服已接入」，输入框切到人工通道；
4. 坐席发一句 → 患者端蓝色「客服」气泡秒到；
5. 坐席点「结束会话」→ 患者端 AI 立刻接回，可以继续问，也可以再次转人工。

口播：「AI 静默期间不再调模型，只落库 + 广播；结束会话是 AI 接管，不是把会话关掉。」

## 5:20–6:20 输出治理（60s）

回标签页 A 问「这药能根治咽炎吗」：

- 回答里**不出现「根治」**（流式改写），DEV 面板的 `guardrail.flags` 有 `compliance_rewritten`；
- 说「我胸痛、呼吸困难」→ 回答**开头**就是「立即就医 / 拨打 120」，再谈药理；
- 口播否定句那个坑：「『更不能说它能根治』直接换成『能缓解』意思会反，所以整句改写成
  『不能给出绝对化的疗效承诺』。」

## 6:20–7:30 评估与观测（70s）

1. 终端跑一次 `python tests/eval/run_eval.py` → 50 条、45 秒，输出 recall@5 **0.94** / MRR 0.93 / 拒答 0.94 + 失败样例；
2. 打开 `/admin/observe` → 8 张指标卡、合规拦截按类别、评估区显示刚才那次运行的指标；
3. 打开 `/admin/prompts` → 演示**灰度**：新建一个 v2 设 `testing` + rollout 30，输入 `patient-1` 点「解析命中版本」，
   显示命中哪一版和原因；再「设为 production」一键上线（无需重启）。

## 7:30–8:00 收尾（30s）

三句话讲取舍：

1. **不追求什么都做**：免费模型 + 单机，指标不粉饰（p95 在 5 并发时是 10.6s，瓶颈在模型 API）；
2. **失败样例留在仓库里**：`eval_runs` 有历史，3 条失败清清楚楚；
3. **下一步**：LLM judge 覆盖率规则、Prompt 版本 A/B 的自动回归（Langfuse experiment 已接好）。

## 常见翻车与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 所有接口超时 | 多个 uvicorn 抢 8000 / 早期 `--reload` 留下僵尸进程 | `Get-NetTCPConnection -LocalPort 8000 -State Listen` 看 PID，按端口杀 |
| `/health` 的 checkpointer 是 unavailable | 用 `uvicorn app.main:app` 裸跑（Proactor 事件循环） | 改用 `backend/serve.py`（或 `--reload`） |
| 检索一直拒答 | Milvus 冷启动 / 知识库被重置 | 等 90s，`.\script\dev.ps1 kb` 重灌（会跳过已就绪的文档） |
| 转人工没有实时消息 | 两个标签页用了同一个账号（localStorage 被顶掉） | 登录态已按标签页隔离，仍异常就硬刷新两个标签页 |
| 回答里还有「根治」 | 后端是旧进程 | 重启 `serve.py`，确认 `/health` 正常 |

> 演示前**必录屏**：Milvus 冷启动、模型偶发超时，现场翻车一次印象就没了。
